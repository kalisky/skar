# anthropic-sdk-mini-agent — a worked Skar example

A small, real custom agent (~100 lines) built on the Anthropic Messages
API, with a complete Skar regression test wired around it. This example
demonstrates **what Skar actually catches** for a real agent codebase.

## File map

```text
examples/anthropic-sdk-mini-agent/
  agent.py          # The agent — a thin loop around Anthropic's Messages API.
                    # Takes claude_call + tool_executor as parameters so the
                    # production app and the regression test share the same code.
  tools.py          # Tool schemas (Anthropic format) + real implementations.
  run.py            # Production entrypoint. Calls the real Anthropic API.
                    # Requires ANTHROPIC_API_KEY.
  traces/
    refund_eligible.json   # A captured Skar trace of a happy-path refund flow.
  tests/
    skar_adapter.py        # Skar adapter — scripts Claude + tools from the
                           # captured trace, then runs the REAL agent loop.
    test_refund_eligible.py        # Generated by `skar generate`.
    test_refund_eligible.report.html  # The HTML summary for code review.
```

## Run the test

From this directory:

```bash
pip install pytest                   # only need anthropic if running run.py
PYTHONPATH=. pytest tests/
```

Expect: `1 passed`. The test exercises the real agent's parsing, loop
control, message construction, and final-text extraction. Only the LLM
call and the tool implementations are stubbed.

## What this test actually catches

The Skar adapter scripts Claude (returns the captured tool_use blocks in
order) and the tool executor (returns the captured results), then hands
both to the real `agent.run_agent` function. The agent's *deterministic
code* runs end-to-end. So the test fails on:

- **Loop control bugs.** Try changing `if response.stop_reason != "tool_use":` to
  `if True:` in `agent.py` — the agent now exits after one turn, the test
  fails with a readable diff showing `[] != ['lookup_order', 'process_refund']`.
- **Parsing bugs.** If you change how `block.input` is read or how
  `block.name` is mapped to the tool executor, the test fails.
- **Message construction bugs.** If the agent stops appending assistant
  blocks correctly, the test fails because the loop terminates differently.
- **Final-text extraction bugs.** If the agent forgets to capture
  `block.text` from the final assistant turn, the `output_text` assertion
  fails.

## What this test does NOT catch

Honest about the limits — these are out of scope by design:

- **LLM behavior changes.** Claude is scripted in the test; we don't call
  the real API. A model upgrade or a temperature tweak could redirect the
  agent in production but won't ring this bell.
- **Tool implementation regressions.** Tool results are replayed from the
  trace; the real `lookup_order` and `process_refund` could quietly start
  returning the wrong shape and this test wouldn't notice. (Those tools
  should have their own unit tests.)
- **System prompt regressions.** If someone edits `SYSTEM_PROMPT`, the
  real agent might pick a different tool sequence — but again, since the
  test scripts Claude, that change wouldn't surface here.

To catch LLM/prompt/system regressions you'd need a different style of
test that actually invokes the real Anthropic API on a recorded scenario.
That has different cost, flakiness, and CI implications. Skar's snapshot-
of-decisions tests and your live-LLM tests are complementary, not
substitutes.

## How the trace was generated

`traces/refund_eligible.json` was crafted by hand for this example so it
is reproducible without an API key. To generate a fresh trace by actually
running the agent:

```bash
export ANTHROPIC_API_KEY=sk-ant-...
python run.py "Please refund order A-1234. The customer reported it never arrived."
```

…and convert the resulting tool sequence into a Skar trace JSON of the
shape in `traces/refund_eligible.json`. A future helper in Skar will
automate this; today it is manual.

## Note about redaction

The captured trace contains a fake leaked token
(`sk-ant-api03-aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa`) embedded in
`lookup_order`'s result. Skar's default redaction caught it before
rendering the test file — `grep "sk-ant-api03-aaaa" tests/test_refund_eligible.py`
returns nothing, and `<REDACTED>` appears in its place. The HTML report
shows the redaction count without exposing the value.

## Regenerating the test + report

If you change the trace, regenerate the test:

```bash
# From the Skar repo root
bun run src/cli/index.ts generate \
  --from-trace examples/anthropic-sdk-mini-agent/traces/refund_eligible.json \
  --out examples/anthropic-sdk-mini-agent/tests/test_refund_eligible.py \
  --test-name refund_eligible_order \
  --note "..." \
  --report examples/anthropic-sdk-mini-agent/tests/test_refund_eligible.report.html
```

The generated test is hand-editable — Skar emits a regular Python file
with named patterns at the top. Add or remove patterns from
`_VOLATILE_PATTERNS` per project.
