# langchain-mini-agent — Skar with LangChain

The same refund-handling domain as the
[`anthropic-sdk-mini-agent`](../anthropic-sdk-mini-agent/) example, but
built with LangChain's `create_agent` graph instead of a hand-rolled
Anthropic-SDK loop. This validates that Skar's capture model
generalizes beyond a single agent shape — specifically, that
**`skar.Recorder.note_call()` works cleanly with LangChain's callback
system** when there's no single tool executor to wrap.

## File map

```text
examples/langchain-mini-agent/
  agent.py             # build_agent(model) — wires create_agent with the
                       # same tools and system_prompt regardless of model.
                       # Production passes ChatAnthropic; tests pass a
                       # scripted fake model.
  tools.py             # @tool functions (lookup_order, process_refund).
  skar_lc_capture.py   # SkarCaptureCallback — a LangChain callback handler
                       # that hooks on_tool_start/on_tool_end and forwards
                       # each call to recorder.note_call().
  run.py               # Production entrypoint. Runs the real LangChain agent
                       # against the real Anthropic API and writes a Skar
                       # trace via SkarCaptureCallback. Requires
                       # ANTHROPIC_API_KEY.
  requirements.txt
  traces/
    refund_eligible.json   # A captured trace of a happy-path refund.
  tests/
    skar_adapter.py        # Runs the real LangChain agent under a scripted
                           # fake LLM. Captured tool calls feed scripted
                           # AIMessage tool_calls; tools run for real.
    test_refund_eligible.py        # Generated by `skar generate`.
    test_refund_eligible.report.html
```

## Run the test

```bash
pip install -r requirements.txt
PYTHONPATH=. pytest tests/
```

Expect: `1 passed`. The test exercises the real LangChain `create_agent`
state machine — graph wiring, tool dispatch, message construction — only
the LLM is stubbed.

## What this test catches (and the difference from the Anthropic example)

The captured tool sequence flows back into the test via the same
`mocked_tool_calls` argument as the Anthropic example. The adapter
hands those tool calls to the **real LangChain agent** running against
a **scripted fake LLM** — the LLM returns AIMessages whose `tool_calls`
match the captured sequence, and the agent's `create_agent` graph
actually executes the LangChain tool-dispatch path.

Concrete things this test fails on:

- **Tool registration regression.** Remove `process_refund` from the
  agent's tool list (`from tools import TOOLS` → `TOOLS = [lookup_order]`)
  and the test fails: the LangChain agent can't dispatch
  `process_refund` and the observed tool sequence comes up short.
- **System prompt regression.** If you change `SYSTEM_PROMPT` in
  `agent.py` *and* that change alters tool selection, the scripted-LLM
  test won't see it — but a `run.py` invocation against the real
  Anthropic API will produce a different trace, which would surface
  the change on the next capture.
- **Graph wiring changes.** If `build_agent` swaps `create_agent` for
  a different orchestration pattern that doesn't dispatch the
  scripted tool calls correctly, the test fails.

Things this test does NOT catch (same boundaries as the other example):
LLM behavior changes (LLM is scripted), real tool implementation drift
(tools run, but you're feeding them the captured input — the result is
whatever the function returns now, not what it returned at capture
time, so this can mask drift if your tool implementation changes
behavior).

## Why a callback handler instead of `recorder.wrap()`?

`create_agent` dispatches tools internally inside its LangGraph state
machine — there's no single `tool_executor` callable for
`recorder.wrap()` to wrap. Skar's `Recorder` was designed with this in
mind: `recorder.note_call(name, args, result)` is the callback-friendly
flow. The LangChain `BaseCallbackHandler.on_tool_start` / `on_tool_end`
pair (in `skar_lc_capture.py`) pairs args with results by `run_id` and
forwards each pair to `note_call`. Net effect: the recorder API surface
is identical, regardless of which framework you're integrating with.

## How traces get produced

```bash
export ANTHROPIC_API_KEY=sk-ant-...
python run.py "Please refund order A-1234. The customer reported it never arrived."
# Wrote Skar trace: examples/langchain-mini-agent/traces/please_refund_...json
```

`run.py` constructs a real `ChatAnthropic` model, invokes the agent
with `SkarCaptureCallback` attached, and writes the resulting Skar
trace JSON to `traces/`. That trace is ready to feed straight into
`skar generate` for a new regression test.

The `refund_eligible.json` shipped in this example was hand-crafted so
the test is reproducible without an API key. Real captured traces will
have slightly different `result` payloads — the recorder JSON-parses
LangChain's stringified tool returns where possible, but the trace's
exact structure depends on what each tool returns.
